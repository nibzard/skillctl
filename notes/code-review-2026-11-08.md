The telemetry consent comparison (telemetry.rs:387) is masked, not broken, by a frozen clock. The two real breakages are the discard-backup collision (apply.rs:821) and the permanent wrong timestamps written across the whole state store. Verdict: a runtime CLI should not honor SOURCE_DATE_EPOCH in its shared clock; the override belongs only in the projection-metadata writer.

### redirect-trust

Confirmed real. The only ureq call site, `HttpTransport::get` (src/discovery.rs:435-440), sets neither `.https_only(true)` nor `.redirects(0)`. Verified in the vendored ureq 2.12.1 source: the agent defaults to `redirects: 5`, `https_only: false` (agent.rs:260-262); `connect` follows Location across up to 5 hops with no scheme or host revalidation (unit.rs:161-236); the per-hop check accepts plain `http`, and the only downgrade guard is the unset `https_only` flag (unit.rs:347-354). The trust gate runs once per command on the pre-redirect URL string at all five sites (discovery.rs:506; source.rs:554, 2101, 2160; planner.rs:2029); no hop is re-checked and `Response::get_url()` is never read. Digest pinning does not mitigate: the digest is declared by the same redirected index, the exact reasoning trust.rs:289-292 gives for refusing plain HTTP. One honest precondition: the first redirect must be issued by the TLS-validated origin or its CDN, so this is a silent-downgrade-on-misconfiguration-or-compromise path, not a pure MitM; but the documented guarantee (trust.rs:357-361) is defeated silently. Git acquisition (source.rs:1819, 2219; planner.rs:2052) delegates to the git CLI, which also follows redirects, yet no skillctl scheme policy exists there (source.rs:2621 accepts http/git/file), so no additional guarantee is lost.

### lock-concurrency

Confirmed real, in three concrete forms. (1) Read commands are not lock-free at open: `LocalStateStore::open_at_for` unconditionally acquires the coordination lock for schema bootstrap (src/state.rs:965), although the common bootstrap path performs reads only (src/state/schema.rs:87-135). So `list`, `history`, `doctor`, `explain`, `tui`, and MCP tool calls wait behind a lifecycle writer and fail after the 15 s default (src/state/lock.rs:23), contradicting src/state.rs:2053-2056 and docs/troubleshooting.md:899-902. (2) A lock-free writer exists: check-mode `skillctl update` persists update_checks, local_modifications, and history through `with_transaction` (src/state.rs:2006), which never calls `coordinate()` (src/planner.rs:204-213), breaking lock.rs's single-writer contract. (3) Lock-free doctor reads `journal::pending_operations` (src/doctor.rs:578) and reports a live transaction's `active` journal as interrupted. Timeout vs hold: update apply, pin, rollback, and restore run `git clone` or HTTP fetch inside the lock (src/apply.rs:2142; src/history.rs:678, 849; src/restore.rs:608), outlasting the 15 s wait; the waiter aborts with LocalStateLockTimeout. Mitigated: single SQLite statements do not tear (60 s busy timeout, task T079), and repair paths take the lock, so no corruption path was found.
